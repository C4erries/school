# Roadmap

Общий план развития проекта. Каждая фаза — это self-contained milestone с рабочим результатом.

> **Статусы**: 🔲 Planned · 🔵 In Progress · ✅ Done · ⏸️ Paused

---

## Фаза 0: Фундамент 🔵
> **Цель**: рабочий скелет проекта, CI-ready, можно начинать писать фичи.

- 🔲 Структура Go-проекта (DDD layout)
- 🔲 Docker Compose: Postgres, Redis, MinIO, Nginx
- 🔲 Конфигурация через env (12-factor)
- 🔲 Миграции БД (выбрать инструмент, первая миграция)
- 🔲 HTTP сервер (chi/echo/gin — выбрать)
- 🔲 Логирование (slog / zerolog)
- 🔲 Healthcheck endpoint
- 🔲 Makefile / Taskfile с базовыми командами
- 🔲 Линтер (golangci-lint)
- 🔲 README с инструкцией запуска
- 🔲 React проект (Vite + TypeScript)
- 🔲 Nginx конфиг (proxy → backend, → frontend)

**Definition of Done**: `docker compose up` запускает всё, healthcheck отвечает 200, фронт показывает "Hello School".

---

## Фаза 1: Аутентификация и пользователи
> **Цель**: регистрация, логин, роли, базовый UI.

- 🔲 Модель User (email, password hash, role)
- 🔲 Регистрация / Логин (JWT + refresh token)
- 🔲 Middleware авторизации
- 🔲 RBAC: student, teacher, assistant, admin
- 🔲 API: CRUD пользователей (admin)
- 🔲 Фронт: страницы логина/регистрации
- 🔲 Фронт: защищённые роуты

**Definition of Done**: можно зарегаться, залогиниться, видеть разный контент по ролям.

---

## Фаза 2: Расписание и бронирование занятий (Ядро MVP v1)
> **Цель**: удобный оффлайн/онлайн помощник репетитора: слоты, бронь, переносы.

- 🔲 Модели: TimeSlot, LessonBooking, RescheduleRequest
- 🔲 Настройка свободных окон преподавателя (сетка слотов)
- 🔲 Форматы: `online` (ссылка на созвон) и `offline` (кабинет/адрес)
- 🔲 Бронирование слота учеником (индивидуально / мини-группа)
- 🔲 Жизненный цикл урока: `scheduled` → `completed` / `cancelled` / `rescheduled` / `no_show`
- 🔲 Механизм переноса урока с подтверждением преподавателем
- 🔲 Фронт: интерактивная сетка расписания ученика и преподавателя

**Definition of Done**: ученик выбирает свободный слот репетитора, бронирует онлайн или оффлайн урок, может запросить перенос, а репетитор отмечает проведенное занятие.

---

## Фаза 3: Финансы и дашборды взаиморасчетов (Tutor Ledger)
> **Цель**: прозрачный учет денег за уроки без эквайринговой бюрократии.

- 🔲 Модели: LessonPricing, PaymentRecord, TeacherBalance
- 🔲 Расчет стоимости урока: доля преподавателя vs процент/комиссия школы
- 🔲 Фиксация ручных платежей (перевод по СБП/карте/наличные) и баланса ученика
- 🔲 **Личный дашборд преподавателя**: заработанные средства, число проведенных занятий, долги учеников
- 🔲 **Сводный дашборд владельца школы**: общая выручка, прибыль школы, расчеты с каждым преподавателем
- 🔲 Фронт: наглядные виджеты баланса и списки должников

**Definition of Done**: после отметки "урок проведен" начисляются деньги репетитору и комиссия школе, виден баланс ученика и прозрачный дашборд для владельца.

---

## Фаза 4: Курсы и адаптивные траектории
> **Цель**: базовые курсы с возможностью подстройки под конкретного ученика.

- 🔲 Модели: CourseTemplate, Module, Lesson, StudentCurriculum
- 🔲 Создание базовой программы обучения (шаблона курса)
- 🔲 Привязка ученика к курсу с кастомизацией тем под его класс/уровень
- 🔲 Хранение методических материалов и конспектов (MinIO)
- 🔲 Фронт: конструктор программы для репетитора и интерфейс прохождения для ученика

**Definition of Done**: репетитор может взять стандартную программу курса и точечно скорректировать её под индивидуального ученика.

---

## Фаза 5: Задания и проверка фото-решений
> **Цель**: быстрая сдача тетрадных фото и удобное рабочее место ассистента.

- 🔲 Модели: Assignment, Submission, SubmissionPhoto, Review
- 🔲 Загрузка пачки фотографий тетради (drag-and-drop, сортировка страниц)
- 🔲 Очередь проверки для ассистентов/преподавателей (`submitted` → `in_review`)
- 🔲 Интерфейс проверки: галерея фото с зумом, поворот, текстовые замечания
- 🔲 Статусы: `approved` или `needs_revision` (с возможностью досыла фото)
- 🔲 Уведомление ученика о результатах проверки

**Definition of Done**: ученик с телефона прикрепляет фото ДЗ, ассистент берет работу из очереди, проверяет в галерее и отправляет фидбек.

---

## Фаза 6: Внешние интеграции (Календарь и Telegram)
> **Цель**: напоминания и синхронизация в привычные приложения.

- 🔲 Интеграция с Google Calendar API (двусторонняя синхронизация слотов)
- 🔲 Telegram-бот для уведомлений:
  - Ученику: напоминание об уроке за 2 часа, статус проверки ДЗ
  - Преподавателю: новая бронь, запрос на перенос
  - Ассистенту: новые работы в очереди

---

## Фаза 7: Видео-стриминг и медиа-контент
> **Цель**: собственные видео-уроки в высоком качестве.

- 🔲 Загрузка тяжелых видео через presigned URL в MinIO
- 🔲 Фоновая обработка видео (FFmpeg / HLS стриминг при необходимости)
- 🔲 Кастомный плеер на фронтенде с запоминанием таймкода

---

## Фаза 8: AI-помощник (Будущее)
> **Цель**: разгрузка репетитора через персонального AI-тьютора.

- 🔲 RAG-поиск по материалам курса и конспектам
- 🔲 Чат-ассистент для ученика с объяснением теории и подсказками по ДЗ
- 🔲 Предварительный анализ решений ассистентом AI
