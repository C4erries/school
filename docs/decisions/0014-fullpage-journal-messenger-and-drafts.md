# ADR 014: Полноэкранный Дневник-Мессенджер (Study Stream), Быстрые заметки ученика и Автосохранение черновиков

## Статус
Принято (Accepted)

## Контекст и Проблематика
1. **Ограничения модальных окон при вдумчивой работе**:
   В Спринте 2.4.1 было создано модальное окно `LessonJournalModal`. Оно идеально решает задачу быстрого ввода отчета за 30 секунд между уроками. Однако когда преподаватель хочет подготовиться к уроку, перечитать историю прогресса за прошлый месяц, продумать программу или зафиксировать мысль вне урока — модального окна недостаточно.
2. **Формат мессенджера как естественный паттерн репетитора**:
   Репетиторы привыкли вести общение и фиксацию договоренностей в Telegram/WhatsApp. Формат «Академического мессенджера» (двухколоночный интерфейс: список учеников + хронологический чат-стрим по центру) дает максимальную скорость навигации и чтения контекста.
3. **Два типа контента в потоке обучения**:
   - *Урочный отчет (Lesson Report)*: привязан к конкретному календарному занятию (тема, оценка понимания 1–5, выданные ДЗ);
   - *Свободная заметка (Quick Note)*: быстрая мысль или заметка преподавателя («Позвонила мама, просила подтянуть тригонометрию», «Забыл тетрадь 3-й раз», «Участвует в олимпиаде 15 ноября»), не привязанная к конкретному уроку.
4. **Риск потери данных на мобильных устройствах**:
   Репетитор часто начинает писать развернутый отчет с телефона между уроками. Звонок, разрядка батареи или закрытие браузера приводят к потере набранного текста, что вызывает крайнее раздражение пользователя. Необходим механизм локального автосохранения черновиков (Drafts).

---

## Решение

### 1. Архитектура данных: Свободные заметки (`client_notes`)
Для поддержки двух типов сообщений в потоке мессенджера таблица `lesson_journals` дополняется легковесной таблицей свободных заметок по ученику:

```sql
CREATE TABLE IF NOT EXISTS client_notes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    client_id UUID NOT NULL REFERENCES clients(id) ON DELETE CASCADE,
    teacher_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    content TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_client_notes_client_id ON client_notes (client_id);
CREATE INDEX IF NOT EXISTS idx_client_notes_teacher_id ON client_notes (teacher_id);
```

### 2. Полноэкранная страница Дневника (`/teacher/journal`)
* **Маршрут**: `/teacher/journal` (защищенный маршрут в `<AppLayout />`). Поддерживает query-параметр `/teacher/journal?clientId=...` для прямой ссылки на ученика.
* **Двухколоночный layout (Liquid Glass Messenger)**:
  - **Колонка списка учеников (боковая панель)**:
    * Список активных учеников с поиском по имени;
    * Сортировка: **по дате последнего проведенного занятия** (сверху те, с кем урок был только что или недавно);
    * Карточка ученика в списке показывает имя, дату последнего урока, бейдж несданных ДЗ и аватар/инициалы.
  - **Центральная рабочая область (Академический поток / Feed)**:
    * Шапка выбранного ученика с быстрым переходом в CRM и отображением баланса часов;
    * Хронологическая лента (Chat Stream), объединяющая:
      1. *Карточки уроков*: дата, тема, чип оценки 1–5, заметки, выданное ДЗ со статусом;
      2. *Карточки свободных заметок*: время создания, текст заметки, кнопка удаления;
    * Нижняя панель ввода (Message Input Bar в стиле Apple Liquid Glass): поле для быстрой отправки заметки + кнопка вызова отчета по последнему уроку.

### 3. Сквозная навигация между расписанием, CRM и журналом
1. **Из карточки ученика в CRM (`/teacher/clients`)**:
   Кнопка «Дневник & ДЗ» в `ClientCard.tsx` осуществляет переход на `/teacher/journal?clientId={id}`, сразу открывая ленту этого ученика.
2. **Из модального окна расписания (`LessonJournalModal`)**:
   В модальное окно добавляется кнопка «Перейти в журнал» (иконка `ExternalLink`), которая открывает полноэкранный журнал с фокусом на этом занятии.

### 4. Автосохранение черновиков отчетов (Client-Side Draft Engine)
* По мере ввода текста в `LessonJournalModal` или на странице журнала поля (`topic`, `notes`, `performance_score`, `homework_title`, `homework_due_date`, `homework_description`) автоматически сохраняются в `localStorage` по ключу `journal_draft_${lessonId}` (debounced 300ms).
* При повторном открытии модалки или страницы поля автоматически восстанавливаются, если на сервере отчет еще не сохранен (с ненавязчивым индикатором «Восстановлен черновик»).
* При успешной отправке отчета на бэкенд черновик в `localStorage` немедленно удаляется.

---

## Последствия
- Репетитор получает удобное рабочее место в привычном формате мессенджера для ведения долгосрочного контекста обучения.
- Появляется поддержка свободных заметок по ученику, не привязанных к конкретному уроку.
- Исключается потеря набранного текста при сбоях сети или разрядке устройства.
- Сохранена полная преемственность с быстрым вводом через модальное окно в расписании.
