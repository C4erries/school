# ADR-009: Журнал платежей (Payments Ledger), Взаиморасчеты с партнерами и Экспорт данных

## Статус
Принято (Accepted) — Фаза 2.2, Спринт 2.2.1

## Контекст
В Спринте 2.1 был внедрен почасовой учет абонементов (`client_subscriptions` с форматами `individual`, `pair`, `group`). Однако система учитывала только остаток часов, не сохраняя историю реальных денежных транзакций:
1. Репетитор не видел историю оплат: кто, когда, сколько рублей перевел и каким способом (СБП/перевод на карту/наличные).
2. Задолженности учеников с отрицательным балансом (`balance < 0`) не пересчитывались в рубли для выставления счета.
3. Комиссии партнерских школ рассчитывались динамически в финансовом дашборде, но не было механизма фиксации выплат и актов за расчетный месяц.
4. Отсутствовал бэкап и выгрузка данных в Excel.

## Принятое решение

### 1. Архитектура учета платежей (Ledger)
- Создается таблица `payments` (миграция `000008`):
  - `id UUID PRIMARY KEY`, `teacher_id`, `client_id`, `amount NUMERIC(10, 2)`, `hours NUMERIC(10, 2)`, `format`, `payment_method` (`transfer`, `cash`, `card`, `other`), `paid_at`, `notes`, `created_at`.
- При внесении платежа через эндпоинт `POST /api/v1/finance/payments`:
  - В единой транзакции создается запись в `payments` и начисляются часы в `client_subscriptions` нужного формата.
  - Сохраняется обратная совместимость с простым добавлением часов.

### 2. Контроль дебиторской задолженности
- Для каждого ученика с суммарным балансом `< 0` рассчитывается сумма задолженности:
  $$\text{Debt}_{\text{RUB}} = \sum_{\text{format}} |\text{balance}_{\text{format}}| \times \text{rate}_{\text{format}}$$
- В интерфейсе Бухгалтерии выводится сводная карточка дебиторки и бейджи долга с кнопкой быстрого приема оплаты.

### 3. Взаиморасчеты с партнерскими школами (Partner Payouts)
- Создается таблица `partner_payouts`:
  - `id UUID PRIMARY KEY`, `teacher_id`, `tag_id`, `period_month VARCHAR(7)` (например, `2026-10`), `gross_amount`, `commission_amount`, `paid_at`, `notes`.
- Сервис рассчитывает проведенные уроки учеников с соответствующим тегом за выбранный месяц. При нажатии «Отметить выплату» создается запись фиксации с датой и примечанием.

### 4. Экспорт данных
- Экспорт через потоковые эндпоинты `/api/v1/export/{clients,lessons,payments}`.
- Для CSV файлов обязательно добавляется UTF-8 BOM (`\xEF\xBB\xBF`) для автоматического распознавания кириллицы в Microsoft Excel на Windows/macOS.

## Последствия
- Полноценная финансовая прозрачность для репетитора.
- Четкое разделение денежных потоков и баланса учебных часов.
- Безопасность данных: возможность локального бэкапа в Excel в любой момент.
