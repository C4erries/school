# ADR 012: Регулярные занятия (Recurring Lessons), стандарт RFC 5545 RRULE и совместимость с Google Calendar

## Статус
Принято (Accepted)

## Контекст и Проблематика
1. **Специфика репетиторского бизнеса**:
   Расписание преподавателя на 85–90% состоит из циклических занятий (например, «Вторник и Четверг в 17:00 с учеником X до конца учебного года»). Отсутствие повторяющихся занятий заставляло пользователя вручную создавать десятки уроков каждую неделю.
2. **Проблема хранения регулярных событий**:
   Наивная генерация сотен физических строк в таблице `lessons` на год вперед приводит к лавинообразному раздуванию БД, невозможности работы с бессрочными сериями и колоссальным сложностям при массовом переносе времени или отмене цепочки занятий.
3. **Стандарт Google Calendar (The Google Calendar Pattern)**:
   При редактировании или отмене повторяющегося урока пользователь ожидает стандартное для индустрии поведение выбора области действия:
   - *«Только этот урок»* (создание точечного исключения);
   - *«Этот и все последующие»* (разделение серии на две части со смещением параметров);
   - *«Все уроки серии»* (глобальное обновление исходного правила).
4. **Синхронизация и импорт из Google Calendar**:
   Интеграционный iCal-фид (`feed.ics`) должен транслировать серии в понятном для внешних календарных клиентов формате (RFC 5545 `RRULE`, `EXDATE`, `RECURRENCE-ID`), а система должна поддерживать импорт `.ics` файлов из Google Календаря для бесшовного онбординга репетиторов со своим накопленным расписанием.

---

## Решение

### 1. Архитектурная модель данных: Виртуальные слоты + Материализация исключений
Вводится новая таблица `lesson_series` для хранения правил генерации циклов, а таблица `lessons` расширяется для хранения материализованных исключений и проведенных занятий:

```sql
CREATE TABLE lesson_series (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    teacher_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    client_id UUID NOT NULL REFERENCES clients(id) ON DELETE CASCADE,
    classroom_id UUID REFERENCES classrooms(id) ON DELETE SET NULL,
    title VARCHAR(255) NOT NULL DEFAULT 'Занятие',
    rrule VARCHAR(255) NOT NULL, -- "FREQ=WEEKLY;BYDAY=TU,TH"
    start_time_of_day TIME NOT NULL, -- 17:00:00
    duration_minutes INT NOT NULL, -- 60
    format VARCHAR(50) NOT NULL, -- individual, pair, group
    location_or_url TEXT,
    notes TEXT,
    start_date DATE NOT NULL,
    until_date DATE, -- NULL если бессрочно
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Расширение таблицы lessons
ALTER TABLE lessons 
    ADD COLUMN series_id UUID REFERENCES lesson_series(id) ON DELETE CASCADE,
    ADD COLUMN original_start_time TIMESTAMPTZ; -- Recurrence-ID для точечных исключений
```

### 2. Динамический алгоритм выборки расписания (`GET /schedule/lessons?from=...&to=...`)
1. Сервис расписания извлекает все физические уроки из `lessons` в окне дат `[from, to]`.
2. Извлекает все активные `lesson_series` преподавателя, пересекающиеся с окном `[from, to]`.
3. По правилу RRULE вычисляет виртуальные временные слоты на запрошенный интервал.
4. Выполняет слияние (Merge):
   - Если на виртуальную дату найдена материализованная запись в `lessons` (с совпадающими `series_id` и `original_start_time`):
     - Если статус `cancelled` — виртуальный слот подавляется (скрывается или помечается отмененным).
     - Если статус `completed` или время перенесено — отдается материализованный урок с актуальными данными.
   - Если записи нет — генерируется виртуальный `LessonDTO` со статусом `scheduled` и флагом `is_recurring: true`.
5. Фронтенд получает монолитный унифицированный список занятий без необходимости знать детали виртуализации.

### 3. Трехуровневое редактирование (Google Calendar Pattern)
* **Только этот урок (`scope = this_only`)**:
  - Создается физическая запись в `lessons` со статусом `cancelled` (при отмене) или новым временем/кабинетом (при переносе), с указанием `series_id` и `original_start_time`.
* **Этот и все последующие (`scope = this_and_following`)**:
  - Исходная серия обрезается: `until_date = occurrence_date - 1 день`.
  - Создается новая серия `lesson_series` с даты текущего урока (`start_date = occurrence_date`) с новыми параметрами (время, кабинет, формат).
* **Все уроки серии (`scope = all_in_series`)**:
  - Обновляются глобальные поля исходной записи `lesson_series` (время суток, продолжительность, формат, ссылка/кабинет).

### 4. Взаимодействие с Абонементами и Прогнозом
* **Абонементы**: Списание баланса часов ученика происходит **исключительно по факту проведения** урока (`POST /lessons/{id}/complete`). При вызове для виртуального урока он сначала материализуется в физическую запись `completed`, после чего списывается длительность занятия.
* **Финансовый прогноз (`/analytics/forecast`)**: Виртуальные слоты в горизонте планирования автоматически участвуют в расчете потенциального дохода наравне с разовыми уроками (кроме дат явных исключений `cancelled`).

### 5. Google Calendar Совместимость: iCal Feed и Импорт `.ics`
1. **RFC 5545 генерация в `feed.ics` и `export.ics`**:
   - Каждая серия выгружается как единый `VEVENT` с параметром `RRULE:FREQ=WEEKLY;BYDAY=...;UNTIL=...`.
   - Точечные отмены выгружаются как параметр `EXDATE:YYYYMMDDTHHMMSSZ`.
   - Точечные переносы выгружаются как отдельные `VEVENT` с директивой `RECURRENCE-ID:YYYYMMDDTHHMMSSZ`.
   - Внешние клиенты (Google Calendar, Apple Calendar) корректно отрисовывают цепочки и исключения без дублирования.
2. **Импорт расписания из Google Calendar (`POST /integrations/calendar/import`)**:
   - Загрузка стандартного `.ics` файла, экспортированного из Google Календаря или других сервисов.
   - Парсинг VEVENT (определение времени, названия, описания и параметров RRULE).
   - Создание разовых уроков и серий в расписании репетитора с защитой от дублирования.

---

## Последствия
- Репетитор получает полноценный опыт Google Calendar с автоматическим заполнением расписания на весь год.
- База данных остается компактной и быстрой (нет захламления миллионами пустых записей).
- Полная совместимость с экосистемой Google/Apple Calendar через RFC 5545.
- Финансовый прогноз становится по-настоящему точным и автоматическим.
