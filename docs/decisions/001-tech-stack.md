# ADR-001: Технологический стек

**Дата**: 2026-10-04
**Статус**: Accepted

## Контекст

Начинаем pet-проект онлайн/оффлайн школы. Нужно выбрать технологии, с которыми будем работать на протяжении всей разработки.

## Решение

| Компонент | Выбор | Обоснование |
|-----------|-------|-------------|
| Backend | **Go** | Типобезопасность, производительность, отличная работа с конкурентностью, стандартная библиотека |
| Frontend | **React + TypeScript** | Большая экосистема, много готовых компонентов, TypeScript для типобезопасности |
| БД | **PostgreSQL** | Надёжная, функциональная, отличная поддержка в Go |
| Кэш | **Redis** | Стандарт для кэширования, сессий, очередей |
| Файловое хранилище | **MinIO** | S3-совместимое, легко заменить на настоящий S3 при деплое |
| Контейнеризация | **Docker + Docker Compose** | Стандарт, воспроизводимость окружения |
| Reverse proxy | **Nginx** | Проверенный, простой, быстрый |
| API | **REST (OpenAPI)** | Простота для начала, можно добавить gRPC позже |
| Название | **school** | Рабочее название, может измениться |

## Альтернативы

- **Vue.js** вместо React — рассматривали, но выбрали React за экосистему
- **gRPC** — отложили, начнём с REST для простоты
- **MongoDB** — не подходит для реляционных данных школы

## Последствия

- Все разработчики (и AI-агенты) используют указанный стек
- Docker Compose — единый способ запуска среды разработки
- Переход на другие технологии — через ADR
