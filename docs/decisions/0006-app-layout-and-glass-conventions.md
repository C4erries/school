# ADR 006: Единый AppLayout и правила верстки Apple Liquid Glass

## Контекст и Проблема
При разработке экрана CRM репетитора (`TeacherClientsPage.tsx`) субагент создал изолированную страницу без использования `<LiquidBackground>` и `<AppNavbar>`, а внутри карточек использовал сплошные серые непрозрачные плашки `bg-slate-50`. В результате страница выпала из стиля Apple Liquid Glass и выглядела как плоский белый лист с блеклыми карточками.

## Решение
1. **Сквозной `AppLayout`**:
   - Вся внутренняя часть приложения (все защищенные роуты) оборачивается единым компонентом `AppLayout`.
   - `AppLayout` содержит в себе:
     ```tsx
     <div className="relative min-h-screen w-full overflow-x-hidden font-sans">
       <LiquidBackground />
       <AppNavbar />
       <main className="max-w-7xl mx-auto px-4 sm:px-6 lg:px-8 py-6">
         <Outlet />
       </main>
     </div>
     ```
   - Отдельным страницам **категорически запрещено** управлять базовым фоном или монтировать свой дублирующий навбар.

2. **Запрет на непрозрачные подложки**:
   - Запрещено использовать утилитарные классы `bg-white`, `bg-slate-50`, `bg-slate-100` внутри `GlassCard`.
   - Для внутренних блоков, списков и плашек использовать только стекло: `bg-white/30 backdrop-blur-md border border-white/40 shadow-sm`.
   - Все компоненты должны использовать токены из `DESIGN_SYSTEM.md`.

## Последствия
- Полная консистентность дизайна на всех существующих и будущих экранах.
- Невозможность появления «белого листа» при создании новых страниц субагентами.
