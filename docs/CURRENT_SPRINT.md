### 📋 Детальное Микро-ТЗ спринта 2.1.2

#### Задача 1: Редактирование ученика в CRM
- **Проблема**: На карточке ученика есть только кнопка «Пополнить абонемент». Если репетитор опечатался в имени, телефоне, ставках или хочет изменить теги школы — сделать это через UI сейчас нельзя.
- **Что делаем**:
  - В шапке карточки ученика рядом с именем добавляем аккуратную кнопку-иконку редактирования (`Edit2` / `Pencil`).
  - При клике открывается модалка `GlassModal` «Редактировать ученика»:
    - Предзаполняются: ФИО, телефон, `rate_individual`, `rate_pair`, `rate_group`, а также уже прикрепленные теги.
    - Внутри доступен тот же мультиселект тегов и возможность создать новый тег на лету.
  - По кнопке «Сохранить изменения» отправляется `PATCH /api/v1/clients/{id}` с обновленными полями.
  - Список клиентов в стейте обновляется локально (или перезапрашивается `loadData()`), карточка сразу показывает свежие данные.

#### Задача 2: Селектор формата занятия в форме урока
- **Проблема**: В модалке создания и редактирования урока в `TeacherSchedulePage.tsx` присутствуют только переключатели «Оффлайн в школе» и «Онлайн урок». Формат занятия (`individual`, `pair`, `group`) не выбирается пользователем, что не дает списывать часы с парных/групповых абонементов и считать корректную ставку.
- **Что делаем**:
  - В модалке «Назначить занятие» и модалке «Редактирование занятия» создаем отдельный блок **«Формат занятия»**:
    - Кнопки: **Индивидуально** (`individual`) | **В паре** (`pair`) | **В группе** (`group`).
  - Блок **«Локация проведения»**:
    - Переключатель: **Оффлайн** (выбор кабинета из списка) | **Онлайн** (ссылка на телемост/звонок).
  - При отправке создания/обновления передаем `format: selectedFormat` (`individual` / `pair` / `group`).
  - В календаре (и Day, и Week View) выводим бейдж выбранного формата (`Индив.` / `Пара` / `Группа`).

#### Задача 3: Исправление верстки тарифной сетки (звездочка `*`)
- **Проблема**: В модалке добавления ученика в 3-колоночной сетке лейбл `ИНДИВИДУАЛЬНО *` разбивается: звёздочка падает на вторую строчку из-за узкой ширины ячейки и заглавных букв.
- **Что делаем**:
  - Добавляем в `GlassInput` поддержку `whitespace-nowrap` для заголовка лейбла.
  - В модалках создания и редактирования задаем неразрывный пробел `Индивидуально&nbsp;*` или разделяем текст и цветную звездочку `<span>*</span>` без разрыва строк.
  - Применяем компактный размер шрифта `text-[11px]` для названий колонок ставок, чтобы даже на компактных экранах текст оставался в одну аккуратную строку.

#### Задача 4: Типизация и API методы
- В `frontend/src/types/schedule.ts` добавляем интерфейс:
  ```typescript
  export interface UpdateClientRequest {
    name?: string;
    phone?: string | null;
    rate_individual?: number;
    rate_pair?: number | null;
    rate_group?: number | null;
    tag_ids?: string[];
  }
  ```
- В `frontend/src/api/schedule.ts` экспортируем функцию `updateClient(id: string, data: UpdateClientRequest): Promise<Client>`.

### 🗄️ Бэклог на будущие фазы (Фаза 2.2+)

#### 📊 Аналитика и финансы
1. **Отдельная страница «Статистика»**:
   - Аналитика по отработанным часам на каждого ученика за неделю/месяц.
   - Процент отмен и неявок по ученикам.
   - Графики динамики заработка и отработанного времени.
2. **Отдельная страница «Бухгалтерия»**:
   - Сводная таблица задолженностей учеников (отрицательные балансы часов).
   - Хронологический журнал финансовых операций (ledger): даты пополнений абонементов и списаний за уроки.
   - Задел под онлайн-эквайринг для учеников/родителей.
3. **Статистика и расчет долгов по партнерским тегам (% школы)**:
   - Сводный финансовый отчет: сколько репетитор должен перечислить партнерским школам по каждому тегу с комиссией.
   - Фиксация выплат школам и расчет чистого дохода.

#### 👥 CRM и ученики
4. **Настраиваемый дефолтный прайс репетитора**:
   - Возможность в настройках профиля выставить свои дефолтные ставки (например: 1500 / 1000 / 700 ₽/ч).
   - При создании нового ученика эти ставки автоматически подставляются в тарифную сетку.
5. **Продвинутый реестр учеников**:
   - Полнотекстовый поиск по имени/телефону.
   - Фильтры по тегам, положительному/отрицательному балансу.
   - Статус ученика: `активный` / `архивный` (`inactive`), возможность архивировать выпускников с сохранением истории.
6. **Ручная корректировка баланса абонементов**:
   - Возможность для репетитора вручную скорректировать баланс часов (откатить списание, начислить компенсацию за сорванный урок).
   - Обязательное поле для комментария/причины ручной корректировки для аудита.

#### 📅 Расписание
7. **Интерактивное выделение интервала в календаре (Drag-to-select)**:
   - Выделение мышью произвольного диапазона времени на сетке для быстрого назначения урока.

#### 🛠️ Архитектура и производительность бэкенда
8. **Рефакторинг и декомпозиция пакетов бэкенда (Clean Architecture / Subpackages)**:
   - Декомпозиция перегруженных директорий (`adapters/httpserver` и `adapters/postgres`) на изолированные предметные подпакеты (`auth`, `crm`, `schedule`, `billing/subscriptions`, `tags`).
   - Использование композиции структур (`struct embedding`) для сборки методов репозиториев/сервисов без раздувания монолитных типов.
9. **Внедрение Client-Side Caching (CSC) через Valkey**:
   - Использование `client.DoCache(...)` из `valkey-go` для горячего in-memory кэширования профилей, расписания и кабинетов с автоинвалидацией по RESP3.
