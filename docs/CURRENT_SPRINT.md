## Текущая фаза: 2.2.1 — Финансовая бухгалтерия, Журнал оплат, Взаиморасчеты с партнерскими школами и Экспорт данных 🔵 (В РАБОТЕ)

### Цель спринта
1. **Полноценный финансовый учет (Payments Ledger)**:
   - Переход от простого учета часов к учету живых денег: создание таблицы платежей `payments` (сумма в ₽, часы, формат, метод оплаты: перевод/СБП/наличные, дата, комментарий).
   - При начислении абонемента репетитор может сразу зафиксировать сумму оплаты и способ расчета.
2. **Сводная таблица задолженностей и балансов**:
   - Контроль дебиторской задолженности: фильтр по должникам (`баланс < 0`), расчет суммы долга в рублях (`|часы| × ставка`), предупреждения об окончании абонемента ($\le 1$ ч).
   - Быстрое принятие оплаты прямо из карточки должника в один клик.
3. **Взаиморасчеты с партнерскими школами (% комиссии по тегам)**:
   - Автоматический расчет доли партнерских школ за выбранный расчетный период (месяц): общая выручка по ученикам школы, процент комиссии школы, сумма к перечислению партнеру.
   - Фиксация выплат школам в таблице `partner_payouts` (с историей и статусом).
4. **Экспорт базы данных (CSV / JSON)**:
   - Выгрузка реестра учеников, расписания уроков и журнала оплат.
   - Формат CSV с кодировкой UTF-8 BOM для корректного открытия в Excel на любых ОС.
5. **E2E верификация**:
   - Прогон `make test`, `make test-e2e` в Docker и `npm run lint && npm run build`.

### 📋 Детальное Микро-ТЗ спринта 2.2.1

#### Задача 1: Модели данных и миграция 000008
- **Миграция `000008_finance_and_payments.up.sql`**:
  ```sql
  CREATE TABLE IF NOT EXISTS payments (
      id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
      teacher_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
      client_id UUID NOT NULL REFERENCES clients(id) ON DELETE CASCADE,
      amount NUMERIC(10, 2) NOT NULL,
      hours NUMERIC(10, 2) NOT NULL,
      format VARCHAR(50) NOT NULL CHECK (format IN ('individual', 'pair', 'group')),
      payment_method VARCHAR(50) NOT NULL DEFAULT 'transfer' CHECK (payment_method IN ('transfer', 'cash', 'card', 'other')),
      paid_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
      notes TEXT,
      created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
  );

  CREATE INDEX IF NOT EXISTS idx_payments_teacher_id ON payments (teacher_id);
  CREATE INDEX IF NOT EXISTS idx_payments_client_id ON payments (client_id);
  CREATE INDEX IF NOT EXISTS idx_payments_paid_at ON payments (paid_at);

  CREATE TABLE IF NOT EXISTS partner_payouts (
      id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
      teacher_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
      tag_id UUID NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
      period_month VARCHAR(7) NOT NULL, -- Формат YYYY-MM
      gross_amount NUMERIC(10, 2) NOT NULL,
      commission_amount NUMERIC(10, 2) NOT NULL,
      paid_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
      notes TEXT,
      created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
  );

  CREATE INDEX IF NOT EXISTS idx_partner_payouts_teacher_id ON partner_payouts (teacher_id);
  CREATE INDEX IF NOT EXISTS idx_partner_payouts_tag_id ON partner_payouts (tag_id);
  ```
- **Доменные модели Go**: `domain.Payment`, `domain.PartnerPayout`.

#### Задача 2: Backend API и Сервисы
- **Эндпоинты в `api.yaml`**:
  - `GET /api/v1/finance/summary?month=YYYY-MM`: общая сводка (поступило денег, сумма долгов клиентов в ₽, начислено комиссий партнерам).
  - `GET /api/v1/finance/payments`: журнал оплат с фильтрами по `client_id`, `from`, `to`.
  - `POST /api/v1/finance/payments`: внесение платежа. При создании платежа автоматически пополняется баланс часов абонемента нужного формата у клиента.
  - `GET /api/v1/finance/partner-settlements?month=YYYY-MM`: расчет выплат партнерским школам (по тегам) за месяц с историей статусов.
  - `POST /api/v1/finance/partner-payouts`: фиксация выплаты партнерской школе за месяц.
  - `GET /api/v1/export/clients`: экспорт базы учеников в CSV (UTF-8 BOM).
  - `GET /api/v1/export/lessons?from=...&to=...`: экспорт расписания в CSV.
  - `GET /api/v1/export/payments?from=...&to=...`: экспорт журнала оплат в CSV.

#### Задача 3: Frontend — Страница «Бухгалтерия» и Экспорт
- **Маршрут**: `/teacher/finance`, ссылка с иконкой `Receipt` в `AppNavbar.tsx`.
- **Компоненты** в `frontend/src/features/finance/components/`:
  - `FinanceSummaryCards.tsx`: 4 метрики (Собрано оплат за месяц, Сумма задолженностей учеников, Комиссии партнерских школ к выплате, Активные абонементы).
  - `DebtsAndBalancesTable.tsx`: таблица должников (`баланс < 0`), расчет суммы долга в рублях, быстрая кнопка «Принять оплату».
  - `PaymentsLedgerTable.tsx`: реестр поступивших оплат с возможностью фильтрации по ученикам, датам и способам расчета.
  - `AddPaymentModal.tsx`: модалка внесения оплаты с авторасчетом ориентировочной суммы по ставке формата и выбором способа (`Перевод на карту / СБП`, `Наличные`, `Другое`).
  - `PartnerSettlementsCard.tsx`: интерактивная карточка взаиморасчетов со школами с расчетом комиссии и кнопкой «Отметить выплату».
  - `ExportModal.tsx`: модалка выбора экспорта (Клиенты, Уроки, Платежи) с мгновенным скачиванием CSV файла.
