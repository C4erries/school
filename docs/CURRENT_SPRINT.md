## Текущая фаза: 2.1 — Шлифовка UX, Недельный Календарь, Учет в часах и Динамические Теги 🟢 (ЗАВЕРШЕНА)

### Цель спринта
1. Перевести систему на полный **учет в часах** с тарифной сеткой ставок (индивидуально, в паре, группа) и форматными абонементами ([ADR-007](decisions/0007-hourly-rates-and-format-subscriptions.md)).
2. Устранить расхождения дизайна в CRM репетитора с помощью сквозного `AppLayout` ([ADR-006](decisions/0006-app-layout-and-glass-conventions.md)).
3. Починить вывод баланса абонементов на карточке ученика и зачистить моки («Анна Кузнецова»).
4. Расширить расписание недельным видом (Week View) с крупными именами учеников, быстрым созданием урока в 1 клик и отметкой проведения прямо на сетке.
5. Реализовать систему динамических тегов учеников (мультиселект + создание на лету с % школы).
6. Настроить доступ к платформе по локальной сети (LAN / Wi-Fi).

### 📋 Детальное Микро-ТЗ по каждой задаче

#### Задача 1: Сквозной `AppLayout` и редизайн CRM
- **Проблема**: Страница `TeacherClientsPage` выпала из стиля, так как не содержала фонового канваса и навбара, а внутри использовались глухие `bg-slate-50`.
- **Что делаем**:
  - В `frontend/src/shared/components/AppLayout.tsx` создаем сквозной layout:
    ```tsx
    <div className="relative min-h-screen w-full overflow-x-hidden font-sans">
      <LiquidBackground />
      <AppNavbar />
      <main className="max-w-7xl mx-auto px-4 sm:px-6 lg:px-8 py-6">
        <Outlet />
      </main>
    </div>
    ```
  - В `App.tsx` оборачиваем все защищенные маршруты в `<Route element={<AppLayout />}>`.
  - В `TeacherClientsPage` переверстываем карточки: внутренние плашки делаем полупрозрачными `bg-white/30 backdrop-blur-md border border-white/40 shadow-sm`, улучшаем типографику и скругления.

#### Задача 2: Тарифная сетка ставок и абонементы по форматам (ADR-007)
- **БД (Миграция `000005_hourly_rates_and_format_subscriptions.up.sql`)**:
  - В таблицу `clients`:
    - `ALTER TABLE clients ADD COLUMN rate_individual NUMERIC(10,2) NOT NULL DEFAULT 0;`
    - `ALTER TABLE clients ADD COLUMN rate_pair NUMERIC(10,2) DEFAULT NULL;`
    - `ALTER TABLE clients ADD COLUMN rate_group NUMERIC(10,2) DEFAULT NULL;`
    - Переносим существующие `base_rate` в `rate_individual`.
  - В таблицу `client_subscriptions`:
    - Добавляем поле `format VARCHAR(50) NOT NULL DEFAULT 'individual' CHECK (format IN ('individual', 'pair', 'group'));`
    - Поле `type` удаляем (так как учет теперь всегда в часах).
  - В таблицу `lessons`:
    - Поле `format` теперь принимает: `individual`, `pair`, `group` (а признак онлайн/оффлайн определяется наличием `classroom_id` / `location_or_url`).
- **Списание часов**:
  - Длительность урока рассчитывается с точностью до минут в долях часа: `hours = (endTime - startTime).Seconds() / 3600.0`.
  - При `complete` списывается точное количество `hours` с абонемента ученика, соответствующего формату урока.

#### Задача 3: Агрегация баланса часов в CRM
- **Бэкенд**:
  - В ответе `GET /api/v1/clients` возвращаем структуру `balances`:
    ```json
    {
      "individual_hours": 8.5,
      "pair_hours": 4.0,
      "group_hours": 0.0,
      "total_hours": 12.5
    }
    ```
- **Фронтенд**:
  - На карточке ученика выводим чипсы остатков:
    - Мятный бейдж: `8.5 ч индив.`
    - Синий бейдж (если есть): `4 ч пара`
    - Если часов нет: нейтральный бейдж `0 ч`
    - Если отрицательный баланс: красный бейдж `–1.5 ч (долг)`
  - Модалка «Пополнить абонемент»: выбор формата (Индивидуально / В паре / Группа) + ввод количества часов (например, 10). После нажатия «Сохранить» баланс на карточке обновляется мгновенно.

#### Задача 4: Полная зачистка моковых данных
- В `frontend/src/api/schedule.ts` полностью удаляем массивы `defaultLessons`, `defaultClients`, `defaultClassrooms`, а также fallback в `localStorage`.
- Если бэкенд не отвечает — фронтенд выводит понятный Glass-баннер ошибки с кнопкой «Повторить запрос». Никаких сторонних фамилий («Анна Кузнецова») в интерфейсе не появляется.

#### Задача 5: Календарь на неделю (Week View)
- В `TeacherSchedulePage.tsx` в верхней панели добавляем переключатель: `[ День | Неделя ]`.
- **Компонент `WeekView`**:
  - Сетка из 7 колонок (Пн, Вт, Ср, Чт, Пт, Сб, Вс) текущей недели.
  - Временная шкала слева: 08:00 – 22:00 с шагом в 1 час.
  - Уроки размещаются по времени: `top = (start - 08:00)`, `height = duration`.
  - При нахлёсте занятий в один день карточки делят ширину колонки (50% / 50% со смещением), как в Apple Calendar.
  - Стрелки `←` и `→` переключают недели вперед/назад, кнопка «Сегодня» возвращает на текущую неделю.

#### Задача 6: Крупное имя ученика на карточке расписания
- В блоке урока:
  - 1-я строка: **Имя ученика** — `text-sm sm:text-base font-bold text-slate-900 leading-tight truncate`.
  - 2-я строка: Время (`15:00 – 16:30`) + бейдж формата (`Индив.` / `Пара` / `Кабинет 101` / `Онлайн`).
  - 3-я строка: Тема урока (если заполнена) — `text-xs text-slate-500 truncate`.

#### Задача 7: Быстрое создание урока в 1 клик по таймслоту
- Клик по свободной ячейке времени в сетке расписания (например, клик на 15:00 во вторник):
  - Моментально открывает модалку `GlassModal` «Назначить занятие».
  - Поля «Дата» и «Время» автоматически предзаполнены: дата вторника, время `15:00 – 16:00` (1 час по умолчанию).
  - Репетитору остается только выбрать ученика из выпадающего списка и нажать «Создать».

#### Задача 8: Редактирование и проведение прямо на сетке
- На блоке урока в календаре:
  - Иконка галочки `✓` («Отметить проведенным»): один клик переводит статус в `completed` и списывает часы с абонемента (карточка окрашивается в мягкий мятный цвет).
- Клик по телу карточки урока:
  - Открывает модалку редактирования:
    - Изменение времени начала и окончания.
    - Смена кабинета / онлайн-ссылки.
    - Кнопка «Отменить занятие» (с вводом причины).
    - Кнопка «Сохранить».

#### Задача 9: Динамические теги (мультиселект + создание на лету)
- **БД**:
  - Таблица `tags` (`id UUID PRIMARY KEY`, `teacher_id UUID REFERENCES users`, `name VARCHAR(100)`, `school_percent INT DEFAULT 0`, `color VARCHAR(30)`, `created_at TIMESTAMPTZ`).
  - Таблица связки `client_tags` (`client_id UUID REFERENCES clients`, `tag_id UUID REFERENCES tags`, `PRIMARY KEY (client_id, tag_id)`).
- **UI**:
  - В модалке создания/редактирования ученика поле «Теги» — интерактивный мультиселект.
  - Внутри выпадающего меню кнопка `+ Создать новый тег`.
  - При клике раскрывается компактная форма: [Название тега] и [% школы].
  - Созданный тег моментально добавляется в базу репетитора и сразу отмечается у текущего ученика.
  - Расчет комиссии: для финансовых вычислений берется максимальный `school_percent` среди прикрепленных к ученику тегов.

#### Задача 10: Доступ к платформе по локальной сети (LAN / Wi-Fi)
- В `deploy/nginx/nginx.conf`: меняем `server_name localhost;` на `server_name _;` (принимает запросы по любому IP).
- Проверяем, что Vite WebSocket HMR не падает при заходе по IP (использует `window.location.hostname`).
- В документации и README фиксируем адрес локальной сети: **`http://192.168.0.21/`** (с любого компьютера, ноутбука или телефона, подключенного к тому же Wi-Fi роутеру).

#### Задача 11: E2E автотесты
- Обновляем сьют тестов в Docker (`make test-e2e`):
  - Проверка покупки абонемента в часах под разные форматы (`individual`, `pair`).
  - Проверка списания точных дробных часов (1.5ч).
  - Проверка CRUD тегов и мультиселекта.
  - Проверка создания урока кликом и редактирования.
  - Достижение **100% pass rate**.
