# Контекст проекта «School» (SaaS-Ассистент Репетитора)

> **Для AI-агентов и разработчиков**: Этот документ является главной точкой входа (Onboarding Hub) для понимания продукта, его текущего состояния, архитектурных решений, дизайна и правил работы.

---

## 1. О продукте и текущее позиционирование

Изначально проект задумывался как классическая образовательная платформа (с регистрацией студентов и кабинетами), но на Фазе 2 произошел **стратегический пивот ([ADR-005](decisions/0005-tutor-assistant-pivot.md))**:
- **Продукт**: **SaaS-Ассистент Репетитора (Tutor Assistant)** — автономное single-player рабочее место для частных преподавателей и репетиторов.
- **Ученики НЕ регистрируются в системе**: они заводятся репетитором как клиенты (`clients`) с контактами, тарифной сеткой ставок и абонементами.
- **Ключевой функционал**:
  1. **CRM учеников**: ведение базы учеников, тарифные сетки (индивидуально, в паре, группа), балансы абонементов в часах, динамические теги партнерских школ (% комиссии).
  2. **Интерактивное расписание**: режим дня и недели (Week View на 7 колонок), поддержка нахлёстов занятий (парные/групповые уроки), быстрое назначение в 1 клик по свободной ячейке времени, прямая отметка проведения (`✓`).
  3. **Учет в часах и абонементы ([ADR-007](decisions/0007-hourly-rates-and-format-subscriptions.md))**: абонементы покупаются в часах с разделением по форматам (`individual`, `pair`, `group`), при проведении списывается точная продолжительность в часах (с поддержкой дробных 1.5 ч).
  4. **Финансовый дашборд**: расчет Gross Potential Revenue (потенциал), Net Tutor Income (чистый доход за вычетом комиссий партнерских школ по тегам) и средней ставки в час.
  5. **Сетевой доступ (LAN)**: настроен Nginx (`server_name _;`), платформа доступна внутри локальной Wi-Fi сети (по IP хоста, например `http://192.168.0.21/`).

## 2. Стек технологий и инфраструктура

- **Backend**: Go 1.24, стандартная библиотека `net/http`, OpenAPI-first генерация роутов и типов (`oapi-codegen`), логирование через `log/slog`, конфигурация Viper.
- **Database**: PostgreSQL 16 (миграции `golang-migrate`, текущая версия миграций — `5`).
- **Cache / Storage**: Valkey (сессии и токены, поддержка CSC `valkey-go`), MinIO (S3 storage).
- **Frontend**: React 18, TypeScript, Tailwind CSS, Vite, Lucide-react.
- **Reverse Proxy**: Nginx (проксирует `/api/v1/` на бэкенд и `/` на фронтенд, поддерживает WebSocket HMR).
- **QA Automation**: Python 3.12, `pytest`, `httpx` (изолированные E2E тесты, запускаемые в Docker через `make test-e2e`).

## 3. Дизайн-система: Apple Liquid Glass ([ADR-006](decisions/0006-app-layout-and-glass-conventions.md))

Все экраны приложения оформлены в строгом стиле **Liquid Glass**:
- Задний план: анимированный фоновый канвас `<LiquidBackground />` с мягкими градиентными сферами.
- Сквозной layout: компонент `<AppLayout />` в `frontend/src/shared/components/AppLayout.tsx`, оборачивающий все защищенные маршруты.
- Панели и карточки: полупрозрачные стеклянные поверхности `bg-white/30 backdrop-blur-md border border-white/40 shadow-sm`, скругления `rounded-2xl` / `rounded-3xl`.
- **Категорически запрещены**: непрозрачные белые/серые плашки (`bg-slate-50`, `bg-white` без прозрачности), ломающие ощущение глубины и стекла.
- **Никаких моковых данных**: из кода полностью удалены любые локальные fallback-массивы (`defaultLessons`, `defaultClients`, «Анна Кузнецова»). Интерфейс работает исключительно с реальным API бэкенда.

## 5. Текущее состояние: Спринт 2.1.3

- **Предыдущие спринты (0, 1, 2, 2.1, 2.1.2)**: полностью завершены, заархивированы в `docs/sprints/`, 100% E2E тестов зеленые.
- **Текущий активный спринт**: **Спринт 2.1.3** в [docs/CURRENT_SPRINT.md](CURRENT_SPRINT.md).
- **Фокус спринта 2.1.3**:
  1. Настраиваемый дефолтный прайс репетитора (автоподстановка при создании нового ученика).
  2. Продвинутый реестр и архивация учеников (поиск, фильтры по балансу/тегам, статус активный/архивный).
  3. Ручная корректировка баланса абонементов с аудитом причин.
  4. Client-Side Caching (CSC) через Valkey для справочников.
  5. Декомпозиция монолитного кода фронтенда (распил файлов 1000+ строк на фиче-компоненты).
  6. Оптимизация тестового сьюта (удаление рудиментов, новые E2E тесты).

## 6. Базовые команды разработчика

```bash
# Прогон бэкенд юнит-тестов с проверкой гонок
make test

# Генерация Go-кода из OpenAPI (backend/api/openapi/api.yaml)
make oapi

# Сборка и запуск контейнеров в Docker
docker compose up -d --build

# Запуск полного сьюта E2E автотестов в Docker
make test-e2e

# Проверка линтером и сборка фронтенда
cd frontend && npm run lint && npm run build
```
