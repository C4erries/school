# AI Agent Instructions

> Этот файл читают AI-агенты перед началом работы.
> Если ты AI — **прочитай это первым**.

## Обязательное чтение

1. **[docs/CURRENT_SPRINT.md](docs/CURRENT_SPRINT.md)** — что мы делаем прямо сейчас
2. **[docs/CONVENTIONS.md](docs/CONVENTIONS.md)** — как мы пишем код
3. **[docs/ROADMAP.md](docs/ROADMAP.md)** — общий план (для контекста)

## Правила работы

### Перед написанием кода
- Прочитай `CURRENT_SPRINT.md` и пойми, какая сейчас фаза
- Сверься с `CONVENTIONS.md` по стилю и структуре
- Если задача не описана в спринте — **спроси**, нужна ли она сейчас

### Во время работы
- **Следуй конвенциям** из `docs/CONVENTIONS.md`
- **Не ломай** существующий код — прогони тесты
- **Пиши тесты** для бизнес-логики
- **Коммиты** в conventional commits формате
- **Не добавляй зависимости** без обоснования
- **Не трогай** файлы, не относящиеся к текущей задаче

### После завершения
- Обнови статус задачи в `CURRENT_SPRINT.md`
- Если принял архитектурное решение — создай ADR в `docs/decisions/`
- Убедись что `docker compose up` работает

### Архитектурные решения
- **Не принимай крупные решения сам** (выбор библиотек, изменение структуры)
- Предложи варианты с pros/cons и **спроси пользователя**
- Зафиксируй решение как ADR

### Что НЕЛЬЗЯ делать
- Менять технологический стек без ADR
- Коммитить `.env` файлы с секретами
- Добавлять фичи из будущих фаз без явного запроса
- Игнорировать линтер
- Писать код без обработки ошибок
