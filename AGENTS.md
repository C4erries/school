# AI Agent Instructions

> Этот файл читают AI-агенты перед началом работы.
> Если ты AI — **прочитай это первым**.

## Обязательное чтение (в строгом порядке)

1. **[docs/PROJECT_CONTEXT.md](docs/PROJECT_CONTEXT.md)** — **главный контекст проекта**, пивот Tutor Assistant, архитектура, стек и правила
2. **[docs/CURRENT_SPRINT.md](docs/CURRENT_SPRINT.md)** — **что мы делаем прямо сейчас** (актуальный спринт, задачи, микро-ТЗ, DoD)
3. **[docs/CONVENTIONS.md](docs/CONVENTIONS.md)** — **как мы пишем код** (Go backend, React frontend, стиль Apple Liquid Glass)
4. **[docs/decisions/](docs/decisions/)** — ключевые архитектурные решения (ADR-005 – ADR-010)
5. **[docs/SUBAGENTS_GUIDE.md](docs/SUBAGENTS_GUIDE.md)** — регламент оркестрации субагентов и передачи контекста
6. **[docs/sprints/](docs/sprints/)** — архив завершенных спринтов (для понимания предыстории)
7. **[docs/ROADMAP.md](docs/ROADMAP.md)** — глобальный план развития проекта

## Правила работы

### Перед написанием кода
- Прочитай `CURRENT_SPRINT.md` и пойми, какая сейчас фаза
- Сверься с `CONVENTIONS.md` по стилю и структуре
- Если задача не описана в спринте — **спроси**, нужна ли она сейчас

### Во время работы
- **Следуй конвенциям** из `docs/CONVENTIONS.md`
- **Не ломай** существующий код — прогони тесты
- **Пиши тесты** для бизнес-логики
- **Коммиты** в conventional commits формате
- **Не добавляй зависимости** без обоснования
- **Не трогай** файлы, не относящиеся к текущей задаче

### После завершения
- Обнови статус задачи в `CURRENT_SPRINT.md`
- Если принял архитектурное решение — создай ADR в `docs/decisions/`
- Убедись что `docker compose up` работает

### Архитектурные решения
- **Не принимай крупные решения сам** (выбор библиотек, изменение структуры)
- Предложи варианты с pros/cons и **спроси пользователя**
- Зафиксируй решение как ADR

### Оркестрация субагентов (Для Lead-агента)
- При вызове субагентов строго следуй **[docs/SUBAGENTS_GUIDE.md](docs/SUBAGENTS_GUIDE.md)** и **[ADR-010](docs/decisions/0010-subagent-orchestration-and-prompting.md)**
- Помни: субагенты запускаются в изолированном контексте и **НЕ видят** проектные правила автоматически
- **Правило «Шага 0»**: в системном промпте и тексте задачи ВСЕГДА требуй от субагента сначала прочитать `AGENTS.md`, `docs/PROJECT_CONTEXT.md` и профильный раздел `docs/CONVENTIONS.md`
- Используй 5-блочный шаблон постановки задачи (Контекст, Входные контракты, Скоуп, Ограничения, Критерии приемки)
- Не запускай параллельную разработку frontend/backend без зафиксированного OpenAPI контракта

### Что НЕЛЬЗЯ делать
- Менять технологический стек без ADR
- Коммитить `.env` файлы с секретами
- Добавлять фичи из будущих фаз без явного запроса
- Игнорировать линтер
- Писать код без обработки ошибок
